# Schema upgrade: account data and Strava compliance

This release adds three things to the database. Production runs Hibernate in `validate` mode
(`APP_JPA_DDL_AUTO=validate`), so the app **refuses to boot** until the schema matches. Run the SQL below
**before** deploying the new build. Local H2 databases (`ddl-auto=update`) need nothing.

## The change

```sql
BEGIN;

-- Which runs came from the Strava API (they must be deleted on disconnect and capped by retention).
ALTER TABLE activities ADD COLUMN IF NOT EXISTS strava_api_sourced boolean NOT NULL DEFAULT false;
CREATE INDEX IF NOT EXISTS idx_activity_strava_api_created ON activities (strava_api_sourced, created_at);

-- The runner's own time zone (IANA id such as America/New_York), set from Settings.
ALTER TABLE runner ADD COLUMN IF NOT EXISTS time_zone varchar(64);

-- Remembers runs a runner deleted, so the next Strava sync does not bring them back.
CREATE TABLE IF NOT EXISTS deleted_activity_tombstone (
    id          bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    runner_id   bigint       NOT NULL REFERENCES runner (id),
    provider    varchar(16)  NOT NULL,
    external_id varchar(64)  NOT NULL,
    deleted_at  timestamp(6) NOT NULL,
    CONSTRAINT uk_deleted_activity_tombstone UNIQUE (runner_id, provider, external_id)
);
CREATE INDEX IF NOT EXISTS idx_deleted_activity_tombstone_runner ON deleted_activity_tombstone (runner_id);

COMMIT;
```

The statements are idempotent, so running them twice is harmless. The column and table definitions were
taken from the JPA mappings (`Activity`, `Runner`, `DeletedActivityTombstone`), not written by hand.

## Flagging runs that were already synced

Runs the Strava sync stored before this release have `strava_api_sourced = false`, so disconnect and
retention would not find them. The app flags them itself on the first boot after the upgrade
(`StravaProvenanceBackfill`, idempotent). To do it by hand instead:

```sql
UPDATE activities
SET strava_api_sourced = true
WHERE provider = 'STRAVA'
  AND strava_id IS NOT NULL
  AND source_checksum = 'STRAVA_' || strava_id
  AND strava_api_sourced = false;
```

Runs a runner imported from their own files have a SHA-256 file checksum, never `STRAVA_<id>`, so they are
never flagged and are never deleted by a disconnect.

## What behaves differently after deploying

- `DELETE /api/auth/strava/unlink` now does what its button says: it revokes the token at Strava, clears the
  link and **deletes the runs synced from the Strava API**. Settings asks for confirmation first.
- `GET/POST /api/strava/webhook` and `POST /api/billing/webhook` were blocked by the security rules (they
  named paths no controller serves), so Strava and Stripe could never deliver. They are reachable now.
  Stripe retries a failed delivery for days, so expect a burst of old events right after the deploy; the
  Stripe webhook still verifies its signature.
- Strava webhook events are unsigned, so they are treated as hints: a deauthorization event only makes
  Hermes ask Strava whether access is really gone, and data is deleted only if Strava says so.
- `GET /api/account/export` (a ZIP of the runner's data) and `DELETE /api/account` (needs the body
  `{"confirm":"DELETE"}`; administrator accounts are refused) are new.
- Optional: `APP_STRAVA_RETENTION_DAYS` (default `0`, off) deletes Strava-API runs older than that many days.
- Garmin imports now publish `ActivityIngestedEvent`, like file imports and the Strava sync.
- `.fit.gz`, `.gpx.gz` and `.tcx.gz` files (Strava's export format) import directly or inside a ZIP; each file
  may expand to at most 10 MB.

## Rolling back

Roll the app back first, then (only if you need to) drop what was added:

```sql
DROP TABLE IF EXISTS deleted_activity_tombstone;
DROP INDEX IF EXISTS idx_activity_strava_api_created;
ALTER TABLE activities DROP COLUMN IF EXISTS strava_api_sourced;
ALTER TABLE runner DROP COLUMN IF EXISTS time_zone;
```

Leaving the new columns in place is safe for the previous build, because Hibernate's `validate` mode ignores
extra columns. If you roll back for good, drop `deleted_activity_tombstone`: its foreign key to `runner` would
block any code that hard-deletes a runner.
